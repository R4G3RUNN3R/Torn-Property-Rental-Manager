# Property Rental Manager v0.3.3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the approved v0.3.3 usability release with selectable market-price strategy, configurable sorting and appearance, a separate settings window, better draggable presentation, and immediate listed-property demotion.

**Architecture:** Keep the proven v0.3.2 rental preparation/submission path unchanged. Extend `market-core.js` with explicit pricing-basis selection, add a small pure `ui-core-v033.js` for settings/sorting/viewport logic, and add `app-v033.js` as a presentation/controller enhancement layer loaded after the stable base app and before bootstrap.

**Tech Stack:** Vanilla JavaScript, Node 20 test runner, JSDOM, Tampermonkey userscript bundle.

**Spec:** Approved chat design from 2026-08-20, captured by the Global Constraints below.

## Global Constraints

- Rental duration remains fixed at exactly 100 days.
- Exact property type and exact upgrades/modifications remain mandatory market comparables.
- Pricing bases offered: lowest, median, average, highest.
- Undercut percentage applies after selecting the pricing base; 0% uses the base exactly.
- Default pricing basis remains average and default undercut remains 0.5%.
- Already-listed `for_rent` properties sort below all unlisted properties; a successful just-listed property moves to the bottom immediately.
- Failed list attempts must not change ordering/state.
- PREPARE RENTAL and LIST PROPERTY safety semantics from v0.3.2 must not be weakened.
- Settings live in a separate gear-opened window; API-key controls stay at the bottom and saved keys are never rendered.
- Main and settings windows are movable/resizable on desktop and remain usable on mobile.
- Dark/light themes remain readable; appearance options include density, images, and full/compact market detail.
